# GPU 优化决策模式

**看到什么证据 → 为什么值得改 → 如何用 TileLang 表达 → 怎样验证 → 何时退出。**

这里是 7 个可复用决策，不是按算子名称排列的代码库。完整核心实现见 [kernels](../kernels/README.md)。范围仅限 GPU；当前证据覆盖 NVIDIA CUDA 和 AMD ROCm，不包含 CPU、NPU、TPU。

## 按当前证据选择

| 分类 | 模式 | 触发线索 | 第一项对照实验 |
| --- | --- | --- | --- |
| 数据搬运 | [P01 消除无效与重复工作](data-movement/eliminate-unnecessary-work.md) | 空 CTA、无效区域、未被消费的结果、重复转换 | 保留语义和缓存更新，只跳过一项已证明无用的工作 |
| 数据搬运 | [P02 匹配数据布局与访问](data-movement/match-layout-to-access.md) | 单独重排/补齐、非合并访存、shared bank conflict | 仅改输出布局或片上布局，比较完整生产消费链 |
| 并行策略 | [P03 选择工作粒度](parallelism/choose-work-granularity.md) | CTA 不够或每 CTA 太小、活跃 warp 不足 | 分别扫描任务拆分与 CTA 大小，计入合并成本 |
| 并行策略 | [P04 按负载分派与选择缓存](parallelism/specialize-by-workload.md) | shape 性能断崖、宽行 spill、不同阶段最佳方案不同 | 比较少量配置及常驻/分段重读方案，寻找交叉点 |
| 融合 | [P05 在明确边界内融合](fusion/fuse-with-explicit-boundaries.md) | 小 kernel 链、中间结果反复写回和重读 | 对比调优后的未融合链，检查中间消费者与舍入 |
| 热循环 | [P06 减少重复指令与活跃状态](compute/simplify-hot-loop.md) | 昂贵指令重复、重复装载、中间值长期存活 | 逐项消融，检查生成代码、指令和寄存器 |

**症状只是候选入口，不是瓶颈诊断。** 先收集能够区分假设的证据，再选择 1–2 个模式；不要同时套用所有技巧。

## 证据如何使用

- **源码事实**：固定 commit 上能看到的控制流、布局和分派条件。
- **上游测量**：作者报告的 GPU、shape、版本和计时范围；没有原始产物时不声称独立复核。
- **机制推断 / 迁移建议**：解释为什么可能有效，必须在目标 GPU 验证。
- **待核验线索**：仅有摘要或缺失代码，不参与定量结论。

本轮从两仓库搜索结果与社区资料中筛选，正式模式引用 **15 条已核实合并的 PR**，另固定 OneFlow、BBuf、CUTLASS 的源码版本。搜索范围不等于完整历史覆盖。[来源登记](SOURCES.md)保留合并 SHA、代码位置、阅读边界及知乎线索。

全部模式为资料分析，**本仓库尚无 GPU 实测**。CUDA/Triton/HIP 经验不能标成已验证的 TileLang 实现；同源移植不能计作独立复现。已有 `kernels/` 案例与 PR 的固定版本可能不同，必须分别记录，不能拼接成一套默认兼容环境。

## Agent 的最小工作流

1. 明确数学语义、GPU、shape/dtype/布局、容差、CUDA Graph 与计时范围。
2. 从上表选择候选，读其反例与退出条件，再读关联核心代码。
3. 在 [workbench](../workbench/) 写下：观察事实、机制假设、最小改动、预期信号、推翻假设的结果。
4. 先验正确性，再交错重复测基线/候选；区分冷/热缓存、profiling 与正常执行、kernel 与全链路。
5. 对接近噪声的收益标记“未确定”。保留失败版本和回退分支；只有目标环境的证据才能升级为本地经验。

## 单篇约定

每篇只保留一个主要决策，包含「触发证据」「决策与 TileLang 落点」「证据与反例」「最小验证与退出」。优先复用完整案例，不放省略同步/尾部处理的伪可运行 kernel，不复制长篇 PR 日志。每项速度数字必须绑定测试条件和测量对象。
