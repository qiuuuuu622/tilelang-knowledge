# P06 减少重复指令与活跃状态

**证明热循环在重复计算或长期保留可消除的状态，再逐项简化，检查编译后的实际变化。**

## 触发证据

- 相邻元素计算相同的昂贵函数，或循环中重复计算可递推/外提的表达式。
- 中间数组跨多个阶段存活，增加寄存器压力或 spill。
- 数据对齐允许向量装载，但生成代码仍有大量独立标量加载。
- 已知配置关闭了某项功能，生成代码仍携带其执行路径。

## 决策与 TileLang 落点

| 候选 | 前提 | 反向成本 |
| --- | --- | --- |
| 局部复用相同值 | 值确实相同，最好由同一线程持有 | 跨线程 shuffle/shared/barrier 可能更贵 |
| 外提或递推 | 数学关系成立，数值误差满足约定 | 浮点误差积累、依赖链变长 |
| 边算边用，缩短活跃区间 | 没有后续使用者 | 重算增加，编译器未必改变分配 |
| 向量访问 | 地址、stride、尾部和对齐合法 | padding、额外寄存器或拆分访问 |
| 编译期特化 | 条件稳定且变体数量有限 | 新增 JIT/预热成本 |

TileLang：检查 `T.Parallel` 的元素归属、fragment 生命周期和复制布局；调整表达式后检查生成 CUDA/PTX 或目标后端代码。源代码变量变少不等于寄存器一定减少。

完整代码入口：[online softmax](../../kernels/reduction/tilelang-online-softmax.md)、[GEMM 显式指令](../../kernels/gemm/tilelang-gemm-intrinsics.md)。这些案例只提供 TileLang 表达参考，不是下列 CUDA 改动的已验证移植。

## 证据与反例

- **源码事实 / CUDA**：[S12](../SOURCES.md#s12) SGLang QKNorm+RoPE 在 interleaved 路径复用相邻元素 sin/cos，用频率递推减少 powf，向量化权重加载，并缩短中间数组生命期、特化 YaRN。NeoX 路径不能直接照搬同线程元素配对。
- **上游测量**：该 PR 报告 B200 上多个测试形状合计加速 1.72–2.45×。它同时修改多项机制，不能将全部收益归因给递推或寄存器减少。
- **归因边界**：其 profiling 表中寄存器/thread 为 30→21，但 achieved occupancy 前后均约 87%。不能写成“occupancy 提升造成加速”；尚需逐项消融证明各因素贡献。
- **否定性线索**：知乎 FlashAttention 复盘提到算术优化可能不改善总时间，见 [Z01](../SOURCES.md#z01)。仅取得片段，具体数字不作为正式证据。

## 最小验证与退出

1. 先测未修改版本的指令、资源和总时间；一次只改变一项，另测组合版本。
2. 对递推覆盖长序列、极端位置、不同精度；对局部复用覆盖不同 layout 与配对方式。
3. 核对生成指令是否实际减少，是否引入 spill/通信，特化是否完成预热。

**退出**：瓶颈不在被删指令；优化已由编译器完成；通信/依赖链或资源成本抵消收益；数值误差越界。保存“不变快”的消融，避免 Agent 重复同一无效尝试。
