# P01 消除无效与重复工作

**先证明工作不影响消费者，再删除它；必要的缓存更新和状态推进必须保留。**

## 触发证据

- 网格按最大容量启动，实际有效长度很短，大量 CTA 立即退出。
- 打分后选择了全部有效元素，或者写出的中间结果根本不被读取。
- 同一元数据转换在多层重复执行，且输入映射在其生命周期内不变。

仅看到很多 kernel 不足以判断冗余：需要沿调用链检查读取者、写入者和复用范围。

## 决策与 TileLang 落点

| 证据成立的条件 | 候选改动 | 需要保留的约束 |
| --- | --- | --- |
| 选择集合已由有效长度确定，不需要分数或排序 | 直接生成等价索引，跳过打分/Top-k | cache 写入、mask、索引格式和下游是否依赖排序 |
| 有效工作远小于分配容量 | 限制网格或用有界网格遍历有效 tile | 最后一个 tile、消费者读取的整页范围 |
| 相同输入和映射被重复转换 | 在已证明有效的范围复用转换结果 | block table、stride、请求身份及生命周期 |

TileLang：从 `T.Kernel` 网格、动态有效长度、tile 循环和 `T.copy` 写入范围入手。用 `empty` 替换初始化前，要证明所有消费者都不读取未写区域；可能需要一次预初始化，而不是每轮清零。

完整实现入口：[QSA 打分](../../kernels/attention/sglang-qsa-mqa.md)。该案例的固定版本与下列 PR 分别追溯，不假设二者逐行相同。

## 证据与反例

- **上游测量 / TileLang 调用链**：[S01](../SOURCES.md#s01) 在 MI355X、GLM-5.2、TP4、输入/输出各 1024 的测试中，`kv_len <= 2048` 时跳过 indexer，报告吞吐提升 2.4%–5.2%。混合长度 batch 中只要有请求超界，就回退完整路径；双图还增加 capture/内存成本。
- **源码事实与上游测量 / TileLang+Triton**：[S02](../SOURCES.md#s02) 将 QSA 工作限制到有效上下文。B200、Qwen3.8-Flash-Next BF16 TP4、指定 MTP/C64 配置的 step 为 28.75→26.54 ms。这是多项工作消除的合计，不能归给单个改动。
- **源码事实 / 复用**：[S03](../SOURCES.md#s03) 只在共享 index group、多层且当前全为 decode token 时复用 sparse MLA 索引转换，不能推广成跨任意层缓存。
- **反例**：[S06](../SOURCES.md#s06) NVFP4 scale 的 padding 被 GEMM 读取，删除初始化后出现 NaN。逻辑上“无效”的位置不一定物理上不可见。

## 最小验证与退出

1. 只删除一类工作；对有效长度边界、混合 batch、重复调用与 graph replay 比较结果。
2. 用 NaN/随机值污染未写区域，检查消费者输出；确认 cache 状态与索引约定仍正确。
3. 同时测被删步骤和完整链，确认判断条件没有引入 GPU→CPU 同步。

**退出**：无法证明读取范围；复用的输入或映射会变；检查/分派成本抵消节省；任何正确性回归。下一步应补数据流证据，而不是扩大跳过范围。
